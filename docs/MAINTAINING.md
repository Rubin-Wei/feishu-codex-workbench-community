# 发布版与个人部署分开维护

社区仓库只保存通用源代码、占位配置、说明和测试。各使用者的 `.env`、`config.local.toml`、`.local/`、SSH 私钥、应用绑定元数据和数据库均留在自己的部署环境。

发布版以独立根提交开始，不包含部署者旧仓库的 Git 历史。后续更新流程：

1. 在开发版本实现并验证通用修复。
2. 将源码导出到新的临时目录，只复制版本控制中的允许文件，排除配置、元数据、运行记录及旧 `.git`。
3. 应用公开配置和文档模板；检查个人名称、路径、域名、应用标识、密钥与会话内容。
4. 将审核后的差异提交到社区仓库，运行 Python 与网页检查，再打版本标签和 Release。

发布脚本不能直接从正在运行的服务目录做整目录复制。公开分支不能 merge 带有个人历史的私有分支，也不应只靠 `.gitignore` 清理已经提交的文件。

当前网页为单用户设计。多人应各自部署；如果开发多用户功能，需要先实现服务端身份到控制器、机器、会话和数据的隔离。
